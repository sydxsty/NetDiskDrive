# NetDiskDrive 使用与实现说明

通过 Windows 盘符使用一个本地容器，并将固定版本中的变化对象同步到百度网盘。主界面使用 WebView2，提供磁盘、快照、云端、块状态、任务日志和设置。

使用新的 `.odv4` 容器格式，只接受本版格式，不读取、转换或迁移旧容器和旧云端对象。旧文件、旧程序和旧状态保留，旧盘请继续用对应旧版程序打开。新盘仍放在 `/OverlayDisk/磁盘标识/`，不创建版本目录。新版磁盘记录与设置保存于 `%LocalAppData%/OverlayDisk/current`；现有登录会话和 WebView2 网页资料保持在其固定位置，可继续使用。

## 开始使用

1. 进入完整发布目录，运行 `OverlayDisk.exe`。需要 Windows x64、.NET 8 Desktop Runtime、WebView2 Runtime。驱动安装入口使用包内官方签名的 WinSpd 安装程序。
2. 新建磁盘，选择容器位置、容量、盘符、4/8/16 MiB 块大小；本地容器为明文。块大小创建后固定，内部页和 NTFS 簇均为 4 KiB。磁盘服务需要管理员授权，主界面和网页登录保持普通权限。程序建立一个 1 MiB 对齐的数据分区，自动格式化为 NTFS、4 KiB 簇并分配盘符。容量上限为 8 TiB，2 TiB 及以上使用 GPT（一个数据卷，可能附带 Windows 保留分区）。创建及挂载可选择只读或读写；只读创建会先完成初始化，再以只读方式重新挂载。
3. 在“云端”登录百度网盘，使用官方网页扫码或验证。缺少 `/OverlayDisk` 时会自动创建；不会额外创建版本目录。登录会话由 Windows 当前用户加密保存，重启无需重复登录，除非会话过期。云端加密在启用同步时选择，派生密钥由当前 Windows 用户 DPAPI 保护保存，密码本身不保存。首次启用后加密方式固定。
4. 为所选磁盘启用同步。可以立即同步，也可按设置的间隔自动同步。后台日志记录每个真正上传的对象及版本提交。准备过程分别显示对象封口、增量索引变化页进度和版本描述生成。

关闭窗口收起到托盘，任务继续运行。从托盘退出会保存并安全卸载磁盘。“退出前同步”默认关闭，可在设置中启用；关闭时不为退出启动上传，未完成任务保留至下次解锁继续。自动同步间隔默认 3600 秒，同时传输对象数默认 4。新默认值用于新配置或缺失字段，已有设置继续按保存值加载。

## 写入和同步

一个 `.odv4` 文件保存数据、页映射、快照、变化记录和本地任务状态。内部页为 4 KiB；不同磁盘位置的小修改可以打包到同一个 4/8/16 MiB 原始对象。已识别的 MFT、日志、USN 等 NTFS 元数据使用独立对象池，识别不出的内容完整保存。

本地写入使用最多 4 个常驻页编码线程，较小批次直接处理；页摘要复用，相邻的索引、数据写入按批处理。完整对象在本次事务内封口时直接使用新生成的明文页及校验信息，不先写盘再读回。未封口旧数据在重启后仍须认证校验。未使用尾部按逻辑零处理，封口不再物理补零；导出和校验时在内存补齐。导入、按需下载和深度整理也只写有效前缀，不自动打洞或执行 TRIM。

上传回执使用容器控制区中的追加日志：普通一批最多 128 条回执只追加一个 4 KiB 页并刷盘一次，重复回执不写盘。未合并回执最多积累 256 个对象，达到边界后批量更新索引；版本发布时确认全部必要对象已经有持久回执。块状态立即显示已确认结果，不必等待索引检查点。重启只回放有界回执日志；损坏或未写完的尾部不会被认作成功上传。

百度目录缓存将同一目录短时间内的回执合并写入，每个日志文件独立刷盘。操作成功仍须等待对应日志持久化；不同目录、低并发或较慢到达的回执可能无法合并，不保证每批都能减少刷盘次数。封口的对象头、索引提交和回执检查点仍有必要的本地写入，这些优化不改变文件 Flush/FUA 的持久性。

写入时维护持久变化集合。相同内容不产生新页版本；普通 Flush 不强制封口每个未满对象。开始同步时固定一个快照根，后续写入进入下一代。增量同步准备只处理该版本的变化页及索引路径，不重新扫描全盘页映射。首次云端恢复复用不可变索引，并有界验证必要索引节点与引用，不为每页重建本地索引或标脏。

设置中的“索引整理缓存上限”用于同步准备阶段的索引和元数据内存缓存，默认每块磁盘 64 MiB，可设置为 16–1024 MiB 的整数，保存后从下次同步任务生效。这是全局偏好，每个正在整理的磁盘分别适用：例如两块磁盘同时整理且设为 64 MiB，两块盘各有 64 MiB 的缓存额度。它与本地容器的磁盘容量上限无关，也不改变上传并发或网盘请求限流。

本地导出的规范对象内容与云端下载解压后的字节相同；本地物理区域的未使用尾部不必为零。有效上传回执命中时不打开对象载荷；需要上传时读取有效前缀一次、在内存补零并校验 SHA-256，然后用 zstd 压缩，按磁盘设置进行云端加密，计算最终传输内容的 SHA-256 和上传分片 MD5。数据块、版本根、提交描述和新建写入者记录均以云端成功回执确认，不再下载回验。下载时先验证并解密云端封装，再自动解压，严格核对原始长度、摘要和认证信息。缓存有效且没有新变化时，即使有等待手动清理的旧块，也不因这些旧块发起网盘请求。

一个远端磁盘只允许一个写者。云端导入提供两种方式：

- **新建副本（默认）：** 创建新的本地磁盘身份，适合从另一台电脑导入。默认关闭云同步，读写挂载的修改只保存在本地。如果以后自行启用同步，需要把引用的基础对象复制到自己的云端目录；这可能下载尚未缓存的源对象，之后按变化增量同步。
- **恢复原硬盘：** 用于原本地容器已删除、且确定没有其他并发写者的情况。必须勾选确认；本机仍有同一身份的磁盘记录、挂载盘或恢复任务时会拒绝。恢复后保留磁盘身份、启动扇区、原云端目录和已发布的同步基线，无修改时不重新上传。再次启用同步仍使用这块盘原有的写入者身份。远端所有权或最新版本变化时会停止，不能用于多人同时写入。

两种方式均按需加载索引和文件内容。选择恢复原硬盘前，请先在设置中移除已不存在的原盘记录；此操作不会删除云端版本。

普通写入可先进入缓存；成功的 Flush/FUA 表示本地持久化，应用保存是否触发它取决于应用；“云端已同步”表示该固定版本已提交。同步期间的新修改单独显示。快照含完整磁盘内容，包括 NTFS 日志；系统 Last Access 设置保持原样，不丢弃时间戳或文件系统写入。快照前刷新文件系统缓存，提供文件系统崩溃一致性，不是 VSS 应用级备份。

## 压缩传输

所有 `.obj` 上传前先以 zstd level 3 压缩；不加密时使用 `zstd-v2`，启用云端加密时使用 `zstd-aes256gcm-v2`。本地对象、数据页及索引均为明文，压缩可以利用实际数据的重复内容和空白尾部。云端加密采用 AES-256-GCM；每盘固定的随机 32 字节盐配合 PBKDF2-HMAC-SHA256 的 600,000 轮派生，密码本身不保存。盐不能消除弱密码的离线猜测风险，请妥善保存强密码。加密版本描述带 HMAC 认证，名称和容量等管理字段仍可见。百度上传按最多 4 MiB 分片，传输封装可能使不可压缩对象略微变大。旧本地布局和旧云端传输封装不兼容，也不自动转换。

下载只接受带当前压缩封装的对象，严格限制输入、输出、窗口大小和单帧范围，拒绝截断、拼接、尾随数据或摘要不符；不会将旧的原始对象当成新格式。界面区分原始对象进度、压缩前待处理量与压缩后已确认上传量；后者不包含协议开销及重试流量。云端旧块清理空间也按压缩前大小估算。没有新变更且回执缓存有效时，不读取对象载荷、不进行压缩，也不访问网盘接口。

## 从云端按需打开

从云端导入时先验证版本记录、根对象和必要的初始索引，随后允许使用；不会为了发现全部文件页先展开整棵索引。挂载 Windows 卷仍会按需取得分区表和 NTFS 必要内容，因此挂载本身可能需要网络读取。界面区分“可使用”和“验证范围”：尚未访问的区域不等于已经完整校验。

只读和读写共用加载路径：沿当前快照的不可变索引查找，需要哪个索引对象就下载哪个，找到数据映射后再下载缺失的数据对象。每个压缩对象解压为该盘规定的 4/8/16 MiB 原始对象，经过长度、摘要和原生认证后缓存在同一个容器中。同一对象的并发读取合并，重复访问使用本地缓存；局部写入只补读保留旧内容所必需的对象，完整页覆盖无需下载旧文件数据，但仍可能需要对应索引路径。

以“接回原盘”导入后，同步只处理本次修改涉及的索引路径，不再为了统计旧对象引用而下载全部容器索引；失败重试继续原任务。尚未展开的来源由读取保护记录保留，手动清理也不会把这些未知引用当成无用对象。若将独立副本首次发布到另一个云端目录，则仍需列出并传送该副本依赖的全部对象；独立副本默认关闭上传。

预取也支持尚未缓存的索引，索引与数据共用设置中的预取数量上限。磁盘卡片分别显示本次打开后下载的索引和数据量（解压后）；后台日志记录对象标识、类型及前台读写、同步或预取等下载原因。此构建保持云端对象格式不变，无需重新导入现有磁盘；使用新引用统计方式写过的本地容器应继续用此构建或后续版本打开。

导入直接复用云端不可变索引，读写挂载只复制发生修改的路径。新建副本的本地磁盘身份与文件修改分别处理。未展开区域不当作空闲，块状态中的数量只统计已经知道的对象；刷新块状态本身不会为补齐统计下载整盘。未设置缓存上限时不自动驱逐；设置上限后可自动淘汰已有可靠云端副本的数据，TRIM 和空间整理仍只由手动按钮触发。

设置可选择关闭、顺序预取或自适应预取，并设置 1–16 个对象的数量上限。顺序策略在连续读取时预取；自适应策略确认连续访问后从少量开始，随着读取增加而扩展。按需请求合并同一对象的并发下载；预取不会形成整盘下载任务。下载失败明确返回读写错误，绝不返回全零来掩盖缺失内容。未缓存内容需要原账户联网；已下载内容和缺块映射在重启后保留。磁盘页显示缓存状态，任务日志区分按需读取、预取与失败。

源云端版本保留持久读取引用，防止尚未下载的内容被手动清理误删。仅从列表移除本地磁盘仍保留此引用；明确删除本地容器后，后续对源盘执行“清理云端旧块”才移除对应引用。缓存和来源记录不含 Cookie。

## 手动加载云端最新快照

在云端导入磁盘的卡片或“云端”页面点击“加载云端最新快照”。程序仅在这时查询来源磁盘的新版本，普通状态刷新和挂载不会自动追随云端更新。只读与读写副本使用相同流程，下载副本不会因此开启云同步或上传本地修改。

1. 先安全卸载磁盘；挂载时按钮不可用，程序也不会代替你自动卸载。关闭的磁盘需要先打开，但不重新挂载；本地打开不需要密码。
2. 程序检查最新版本，并固定本次候选。版本相同且没有本地修改时直接结束，不下载对象内容。
3. 确认目标版本。存在本地修改时，必须确认“丢弃本地修改”后才能加载；即使当前已选择只读，之前读写挂载留下的修改仍会触发警告。对同一云端版本重新加载也可能覆盖本地修改。默认焦点在“取消”。
4. 程序验证必要的根与索引后切换快照，之后保持未挂载。点击挂载继续使用，新快照中尚未访问的内容按需读取。

加载期间不能挂载同一块磁盘，准备和确认阶段可以取消；已经提交快照切换时需要等待结束。确认绑定检查时的本地修订和云端版本，状态改变会拒绝旧确认，需要取消后重新检查。加载失败不应显示完成，原来的本地手动快照仍保留；不会自动新建备份快照，也不会触发本地整理或删除云端旧块。

快照已经切换、但分区身份准备尚未完成时，界面会明确显示剩余工作；下次挂载会先重试身份准备，成功前不会挂载。若只是切换后的界面状态刷新失败，也会说明快照已经加载，避免误认为尚未提交而重复操作。

缓存按来源和对象身份复用，直接加载多代之后的最新根也无需逐代下载。未变化且已经缓存的对象无需再下载；未访问的新对象暂不下载。传输的最小单位仍是现有压缩 `.obj`：对象中只改变 4 KiB 也可能需要取得整个压缩对象，不能把本地页粒度等同于网盘下载粒度。

## 只读挂载与本地缓存上限

每次挂载都可选择只读或读写，并保存为这块磁盘的默认方式；挂载期间不能切换。只读同时受驱动和原生写保护约束，文件写入、扇区写入、TRIM 和格式化会被拒绝。读取不会产生 NTFS 访问时间写入；缓存下载、同步既有内容、快照管理以及保持对象身份的物理整理仍可执行。修改文件前请安全卸载，再以读写模式挂载。

启用同步时可设置本地占用上限，也可在每块磁盘的设置里调整。限额按容器的实际磁盘占用计算，采用软上限：未同步数据、必要索引和当前读取正在使用的空间会保留，允许暂时超过限额。界面显示物理占用、上限、待下载块数和超限提示。不会预先为数 TB 的虚拟容量分配同等大小的 SSD 空间。

三种缓存策略都采用有界候选批次和内存中的访问记录，不因每次读取强制刷盘：

- **通用（LRU 近似）：** 优先保留最近访问的对象。
- **常用文件优先（LFU 近似）：** 优先保留反复访问的对象。
- **顺序读取：** 对视频或备份的连续读取降低保留优先级，减少一次性扫描挤占缓存。

开启限额后，仅已发布且有持久云端读取保护的完整对象可淘汰；尚未同步的修改始终留在本地。对象身份、摘要、页映射和同步代号不因淘汰变化，实际释放采用稀疏打孔，并等待旧读者离开。以后访问该对象时重新下载并校验。缓存上限关闭后，已存在的缺块仍保留读取来源；不会自动把它们全部下载。

从云端导入的副本可以继续借助原版本的读取引用淘汰干净缓存；首次同步到自己的目录时，也不会为了导出而把整个虚拟盘永久塞入本地。原来源与本盘来源按对象分别记录，旧快照仍可读取。缓存保护只需一次小型引用确认，不因每次淘汰逐块调用网盘接口。手动云端清理会再核对本地、快照、上传任务及读取中的引用，不能删除仍可能需要下载的对象。

## 网盘全局限流

设置提供请求频率（0.1–20 次/秒，默认 3）和同时请求数（1–8，默认 4），保存即生效。所有磁盘及其上传、下载、预取、目录查询、重试共享额度，下载正文结束才释放并发名额；低频设置不会闲置后突发放行。正在进行和排队的请求数在“后台任务”显示。官方网页登录窗口自身的网页请求由 WebView2 管理。

PCS 上传节点显式接收网页登录会话中的 BDUSS 和 STOKEN，修复 host-only STOKEN 没有随上传请求发送的情况。上传分片使用有界可定位流，让整个 multipart 请求具有精确 Content-Length，避免百度节点拒绝 chunked 传输（实测 403 / 31211）。未知 HTTP 403 不盲目重试；确认的会话失效提示重新登录。403、认证错误和重试耗尽的 429 会暂停自动同步，检查后需手动继续。同账户可重新验证登录；切换到其他账户或退出登录前，需先关闭按需磁盘。

## 创建中断后的重试

初始化后暂时没有分区属于正常状态，新版先完成分区枚举，再筛选已核验身份的虚拟盘；分区、卷和盘符出现稍迟时会有界等待，不重复执行格式化。当前格式的新盘若停在仅有空分区表的阶段，可重试挂载；只有证明全部已分配页都属于分区表、其余字节为空时才允许续建。已有或无法确认的文件系统不会自动重格式化。

## 手动整理与云端清理

- **普通整理：** 回收无引用对象和可回收的本地 CoW 元数据，释放稀疏空洞并缩短已空的文件尾部。不会读取、搬运或重新打包存活数据对象；不增加待上传对象。支持暂停、继续和停止，重启不自动续跑。
- **深度压紧：** 将完整对象搬到前面的空洞，尝试压紧物理布局。仅改变本地物理位置，保留对象 UUID、摘要和上传回执，逻辑页映射和待上传量不变。相较普通整理会增加本地读写；不再使用旧版逐页重打包的实现。
- **NTFS 空闲空间回收：** 主动读取空闲簇位图并执行 TRIM，然后普通整理。需先关闭该盘文件和程序；锁卷失败不会执行 TRIM。锁卷后直接验证盘内空闲位图；关键元数据布局无法完整识别时会拒绝回收。回收可暂停，继续时重新核对空闲位图。TRIM 确实改变逻辑页映射，其同步变化单独计数；存活对象不因整理被重新打包上传。
- **清理云端旧块：** 云端页单独按钮，展示待删数量和空间估计。只删除已经确认过时且不被恢复任务占用的已知对象。普通同步、无变化检查和启动不会自动删除。暂停后必须手动继续。

磁盘不向 Windows 宣告自动 UNMAP 支持，并拒绝未经用户操作触发的 UNMAP。程序不修改系统全局 TRIM 开关。普通写入可以复用已经安全退役的容器位置，这不涉及内容重新打包或云端删除。

块网格按本地物理位置展示，上传统计按对象身份统计，并单列未缓存在本地的待传对象；下载、淘汰和物理搬迁不会制造新的同步变化。

## 管理和诊断

- **快照：** 创建、命名、删除并恢复到独立新磁盘。恢复支持暂停和重启继续；校验完成前不能挂载。任务引用保护源快照。
- **块状态：** 连续滚动的紧凑网格，按需加载且缓存有界。块号保持物理顺序；拖动图例只改变颜色优先级。自动刷新可以关闭并记住选择，关闭后仍可手动刷新。同步状态、内容类型与引用标记分别展示，快照引用不等于正在上传。
- **统计：** 点击顶部统计按状态或类型筛选。已落盘变化页、缓存中的页版本、当前固定任务剩余工作和后来产生的修改分别计数；估计值有明确标记。逻辑变化字节不等于网络上传字节。
- **刷新：** 块状态点击刷新后立即显示刷新中，成功显示更新时间，失败保留旧结果。
- **同步诊断：** 在“后台任务”选择磁盘并展开查看。同步准备单独列出固定版本、对象封口、增量索引和版本描述的本地读写量、刷盘次数及耗时，以及索引缓存使用与命中情况；这些计数仅属于本次同步任务，按当前进程累计，重启后重新计数。整盘和前台读写、排队及网盘请求另列，不计入准备阶段总量。导出字节包含内存补零，不能当作实际 SSD 读取量；另列逻辑零尾部、回执日志写入和检查点计数。仅查询本地已有计数，不额外请求网盘；离开任务页或收起诊断后停止刷新。
- **日志：** 展示刷新、准备、读取、上传、确认、提交和停留原因，上传对象 ID 可核对。本地保留最近最多 65,536 条记录；界面即时显示，文件缓冲每 128 条或 250ms 写出，正常退出前写完。异常退出可能缺少最后一个短窗口的活动记录；用于恢复同步的持久回执独立保存，不依赖活动日志。
- **磁盘删除：** 设置中可只从列表移除，也可输入名称确认删除本地文件；云端副本保留。挂载、解锁、外部占用或恢复引用会阻止删除。

## 数据与凭据

本地容器不加密，云端数据和内部索引可选先压缩再 AES-256-GCM 加密。每盘固定随机盐与高成本密码派生提高猜测成本；云端密码和本机受保护密钥均遗失后不能恢复，没有整卷防回滚保证。容量、显示名称和对象数量等管理信息仍可见。百度 Cookie 不保存到容器或普通设置 JSON，不读取其他浏览器资料。

当前磁盘设置位于 `%LOCALAPPDATA%\OverlayDisk\current`；登录资料和部分可重建云端缓存使用 `%LOCALAPPDATA%\OverlayDisk\v4` 下的固定位置。缓存按提供商、账户、远端目录、磁盘和写入设备隔离。缓存损坏时核对发布元数据，不能确定来源的云端孤立对象保留。复制容器前先安全卸载并停止相关后台任务。

## 模块和构建

Rust 原生核心经并发管理通道和独立二进制对象通道连接 .NET 磁盘服务。按需下载使用第三条受认证的反向二进制通道，网盘凭据仍只在普通权限主程序中使用。`Cloud.Contracts` 定义后端接口，`Cloud.Sync` 管理发布与恢复，`Cloud.Baidu` 实现私有网页协议，可增加其他后端。

构建需要 Rust stable x64 MSVC、Visual C++ Build Tools 和 .NET 8 SDK：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
powershell -ExecutionPolicy Bypass -File scripts/test-local.ps1
```

安装 WinSpd 后，以管理员身份运行 `scripts/test-local.ps1 -IncludeMount`，只创建新的功能测试容器。格式说明见 `../engine/README-v4.md`，协议来源见 `../cloud/OverlayDisk.Cloud.Baidu/README.md`，验证范围和限制见 `VALIDATION.md`。功能验证与用户提供的 CDM 示例分开记录，不以历史真实账号结果代替当前版本测试。
